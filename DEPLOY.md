# Deploying DevInfantary POS to Render

This repo is configured for [Render](https://render.com) via `render.yaml`
(Render Blueprint). Everything below has been verified locally in production
mode (`DEBUG=false` + WhiteNoise + hashed statics + HTTPS redirect).

---

## 1. One-time setup (Render dashboard)

1. Push the changes to GitHub:
   ```bash
   git add -A
   git commit -m "Responsive layout + Render deployment config"
   git push origin main
   ```
2. In Render: **New → Blueprint** → select this repository → **Apply**.
   Render reads `render.yaml` and creates:
   - the web service `edgen-shop-pos` (free plan, Singapore region)
   - a free PostgreSQL database `edgen-shop-db`
   - `SECRET_KEY` (auto-generated) and `DEBUG=false`
   - `DATABASE_URL` (auto-wired to the database)

3. Wait for the build to finish, then open the service URL.

> **One manual step:** Render cannot infer the real hostname at build time.
> Open the service's **Environment** tab and set
> `CSRF_TRUSTED_ORIGINS` to your live URL, e.g.
> `https://edgen-shop-pos.onrender.com`
> (a `https://*.onrender.com` default is already applied, so this is only
> needed if you later add a custom domain).

---

## 2. How the build works

| Stage | Command |
|---|---|
| Install | `pip install -r requirements.txt` |
| Statics | `python manage.py collectstatic --noinput` |
| Migrations | `python manage.py migrate --noinput` |
| Serve | `gunicorn edgen_shop.wsgi:application --workers 2 --threads 4` |

Static files are served by **WhiteNoise** with hashed filenames and
`immutable` cache headers, so no external CDN is required.

## 3. Environment variables

| Variable | Required | Notes |
|---|---|---|
| `SECRET_KEY` | yes | Auto-generated by the blueprint. If missing, a temporary one is generated (sessions reset on restart). |
| `DEBUG` | yes | Must be `false` in production. |
| `DATABASE_URL` | yes | Injected by Render when the Postgres DB is attached. |
| `CSRF_TRUSTED_ORIGINS` | recommended | Comma-separated, e.g. `https://yourapp.onrender.com`. |
| `ALLOWED_HOSTS` | no | Defaults to `.onrender.com`. Set it if you use a custom domain. |
| `USE_MYSQL` | no | Only for external MySQL; leave `false` when using Postgres. |
| `MYSQL_*` | no | Only for external MySQL. |

### Using external MySQL instead of Postgres
```bash
USE_MYSQL=true
MYSQL_DB_NAME=edgen_shop
MYSQL_USER=...
MYSQL_PASSWORD=...
MYSQL_HOST=...
MYSQL_PORT=3306
```
If `DATABASE_URL` is set it takes priority. In production a configured-but-
unreachable MySQL now raises an error instead of silently falling back to an
ephemeral SQLite file.

## 4. Bringing across the existing local data

The production database starts empty. To copy your current `db.sqlite3`
contents (products, suppliers, bills, etc.) across:

```bash
# 1. Locally - export (the file is git-ignored so it stays private)
python manage.py dumpdata --indent 2 --exclude contenttypes --exclude auth.permission > seed_data.json

# 2. Upload it to Render, then in the Render Shell
python manage.py loaddata seed_data.json
```

Render's **Shell** tab gives you a terminal inside the running service.

## 5. Free-tier caveats

- The free web service **sleeps after ~15 minutes of inactivity**; the first
  request after that takes up to ~1 minute while it wakes.
- The free PostgreSQL instance **expires after 30 days**. After that the
  service will fail to connect and you must upgrade the plan or migrate the
  database.
- Free instances also have monthly runtime hour limits.

## 6. Local production preview

To reproduce the production stack on Windows (gunicorn is Unix-only):

```bash
set DEBUG=false
set SECRET_KEY=<a long random string>
set USE_MYSQL=false
set ALLOWED_HOSTS=localhost,127.0.0.1

python manage.py collectstatic --noinput
python manage.py runserver 127.0.0.1:8000 --noreload
```

`runserver` strips the SSL redirect when the request carries
`X-Forwarded-Proto: https`, which is exactly what Render's proxy sends:

```bash
curl -I -H "X-Forwarded-Proto: https" http://127.0.0.1:8000/
```

You can also run the same config through a Windows-friendly WSGI server:

```bash
python -m pip install waitress
python -m waitress --listen=127.0.0.1:8000 --threads=4 edgen_shop.wsgi:application
```

> Note: `waitress` strips the `X-Forwarded-Proto` header, so with
> `SECURE_SSL_REDIRECT=true` it will always redirect to `https://`. Use
> Django's `runserver` for a faithful local preview, or temporarily set
> `DEBUG=true`.

## 7. Troubleshooting

| Symptom | Fix |
|---|---|
| `ModuleNotFoundError: dj_database_url` | `pip install -r requirements.txt` (it was missing from the machine used to author this). |
| Blank page / 500, no static files | Confirm `collectstatic` ran during the build and `STATIC_ROOT` is writable. |
| `403 Forbidden` on save/login | Set `CSRF_TRUSTED_ORIGINS` to the live HTTPS URL. |
| `Bad Request (400)` with correct host | `ALLOWED_HOSTS` is missing the custom domain. |
| `DisallowedHost` | Same as above. |
| Build fails on Python version | `PYTHON_VERSION` is pinned in `render.yaml` and `.python-version`; keep them in sync. |
| App boots but DB errors | `DATABASE_URL` not attached — re-attach the database in the Render dashboard. |
